# ① 视频源：摄像头地址从哪儿来

> 回到总览：[`docs/引导.md`](../引导.md) ｜ 下一篇：[② 视觉方案](./2-视觉-本地多模态.md)

插件自己**不会**替你编地址，也**不会**自己去公网找摄像头。它需要的信息只有三样：

| 要什么 | 网络摄像头 | 电脑自带 / USB 摄像头 |
|---|---|---|
| **视频源** | RTSP 地址（`rtsp://…`） | 设备名（或留空自动挑） |
| **麦克风** | 一般不用摄像头上的（延迟高），用电脑的 | 设备名（或留空自动挑） |
| **外部程序** | ffmpeg（解流）、python（识别/转写） | 同左 |

---

## 1. 先分清是哪种摄像头

| | 网络摄像头（IPC） | 本机摄像头 |
|---|---|---|
| 长相 | 独立的小方块/球机，插网线或连 WiFi，有 IP | 笔记本屏幕上方那颗 / USB 摄像头 |
| 要不要地址 | **要**，`rtsp://…` | **不要**，留空即可 |
| 配哪儿 | 面板「RTSP 地址」 | 面板「摄像头」（下拉选），留空自动挑 |

> 判断口诀：**要插网线 / 要连 WiFi / 要有 IP** 的才需要 RTSP 地址。
> 本机摄像头填了 RTSP 地址反而会把它顶掉（地址优先）。

---

## 2. RTSP 地址从哪儿拿（按可靠性排序）

### 2.1 摄像头自己的 Web 后台（最准）

1. 先确认摄像头和这台电脑**在同一个网段**（`ipconfig` 看自己的 IP，比如 `192.168.31.25`，那摄像头一般也是 `192.168.31.x`）
2. 浏览器打开 `http://<摄像头IP>`（HTTP 端口常见 80，也有 8000 / 8080）
3. 用管理员账号登录（密码/激活码通常在**机身标签**上）
4. 找这些菜单（各家叫法不同）：
   - 「设置 → 网络 → 高级 → RTSP」
   - 「视频 → 取流地址 / 流媒体」
   - 「配置 → 网络 → 端口」（看 RTSP 端口是不是 554）
5. 有的设备默认**关闭 RTSP**，要先勾上「启用 RTSP」再重启生效
6. 复制那条地址，形如：
   ```
   rtsp://admin:密码@192.168.31.202:554/Streaming/Channels/101
   ```

### 2.2 厂商客户端 / 手机 App

| 品牌 | 在哪儿看 |
|---|---|
| 海康 Hikvision | iVMS-4200（设备 → 远程配置 → 网络 → 高级 → RTSP）；手机 Hik-Connect 多数不显示地址 |
| 大华 Dahua | ConfigTool / 网页后台 → 网络设置 → 端口；DMSS App 不显示 |
| TP-Link（Tapo / VIGI） | Tapo App 里开「摄像头 → 高级 → RTSP」，地址固定为 `/stream1` |
| 萤石 Ezviz | App 里「设备设置 → 更多设置 → 开启 RTSP」，地址里的密码是设备**验证码**（标签上那 6 位大写字母） |
| 小米 / 米家 | 绝大多数**不开放** RTSP，只有部分型号支持 ONVIF —— 不支持就换一种接法，别硬试 |

### 2.3 机身标签 / 说明书

很多机器（尤其海康、大华的工程机）直接印着：

```
RTSP: rtsp://admin:XXXXXX@192.168.1.64:554/Streaming/Channels/101
密码: XXXXXX
```

**先看标签，能省掉上面两步。**

### 2.4 ONVIF（不知道路径时最省事）

装一个免费小工具 **ONVIF Device Manager**（Windows）：

1. 它会自动列出局域网里所有 ONVIF 设备
2. 点开目标设备 → 「Live video」→ 上面直接显示 `Uri` —— **那就是完整 RTSP 地址**
3. 顺手还能看到设备的 ONVIF 端口、型号、固件

> ⚠ 不要「猜」地址：路径少一个字符、端口写成 HTTP 端口，表现都是「连不上」，很难分清是哪种错。
> 只有下面第 3 节的标准路径值得**依次试**。

## 3. 各品牌常见标准路径（拿不到就按这个试）

| 品牌 | 主码流 | 子码流 | 备注 |
|---|---|---|---|
| 海康 Hikvision | `/Streaming/Channels/101` | `/Streaming/Channels/102` | 老固件：`/h264/ch1/main/av_stream` |
| 大华 Dahua | `/cam/realmonitor?channel=1&subtype=0` | `…&subtype=1` | 地址里带 `?`，注意别丢了 |
| 宇视 Uniview | `/media/video1` | `/media/video2` | — |
| TP-Link（Tapo / VIGI） | `/stream1` | `/stream2` | 需先在 App 里开启 RTSP |
| 萤石 Ezviz | `/h264/ch1/main/av_stream` | `/h264/ch1/sub/av_stream` | 密码是「验证码」，且需在 App 开启 |
| 通用 ONVIF 设备 | 用 ONVIF `GetStreamUri` 拿 | — | 别手拼 |

端口：RTSP 默认 **554**；也有 8554 / 10554。**80 / 8000 / 8080 是 HTTP 网页端口，不是 RTSP。**

## 4. 连 IP 都不知道：怎么在局域网里找摄像头

### 4.1 先确定网段

```powershell
ipconfig            # 看 IPv4 地址，比如 192.168.31.25/24
```

### 4.2 三种找法（从省事到费事）

1. **装了 `xpai-camera-control` 技能** → 让它跑 `search_devices`：
   它会用 SK 私有协议 / JCP / WS-Discovery 扫局域网，列出 IP、型号、ONVIF 端口，能连的直接连上。
2. **ONVIF Device Manager** → 自动发现，直接给出 RTSP 地址（见 2.4）。
3. **路由器后台** → 「DHCP 客户端列表 / 在线设备」，找名字像 `IPC`、`Hikvision`、`Dahua`、`Tapo`、`UNV` 的陌生设备。

### 4.3 没有现成工具时，手工探

```powershell
arp -a                                                     # 局域网里有哪些邻居
Test-NetConnection -ComputerName 192.168.31.202 -Port 554  # RTSP 端口通不通（TcpTestSucceeded）
ffmpeg -rtsp_transport tcp -i "rtsp://admin:密码@192.168.31.202:554/Streaming/Channels/101" -t 1 -f null -   # 能不能出流
```

`ffmpeg` 那行只要能解码出帧（不报错退出），就说明地址是对的。

### 4.4 找不到就是没有

局域网里确实没有设备，就**直说**——请用户确认摄像头是否上电、是否连的同一个 WiFi、
是不是插在 NVR 后面（NVR 后面的摄像头可能只对内网开放）。**不要编一个地址糊弄过去。**

## 5. 拿到之后怎么填

| 方式 | 怎么做 |
|---|---|
| **面板** | 设置 → 摄像头桥 → 「RTSP 地址」粘贴进去 → 保存（改完即时生效） |
| **让模型填** | 说「帮我配摄像头，地址是 rtsp://…」→ 模型调 `camera_setup`（`action="set_source"`），存完**当场试一帧** |
| **接口** | `POST /api/camera-bridge/config`，body `{"rtspUrl":"rtsp://…"}` |

密码里如果有 `@ : / # ?` 这类字符，**要做 URL 转义**（`@` → `%40`，`:` → `%3A`，`/` → `%2F`），
否则地址会被解析坏，表现同样是「连不上」。

---

## 6. 怎么验证配通了

1. 面板点「**开画面**」或「**拍一张**」——能看到画面就成了
2. 或者让模型 `look_camera` 拍一张、再 `read_image` 真的看一眼
3. `camera_setup`（`action="set_source"`）会替你试一帧，返回画面尺寸就说明通了
4. 不放心再跑一次「**自检**」：ffmpeg / python / 模型 / 设备一目了然

> **出过一帧画面 = 「视频源」这条引导自动结束**，提示词里那段就不再出现了。

## 7. 报错对照表

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| `401 Unauthorized` / `403 Forbidden` | 用户名或密码错 | 用机身标签上的密码；萤石用「验证码」；确认账号没被锁 |
| `404 Not Found` / `Connection refused`（554 拒绝） | 路径或端口不对 | 对照第 3 节品牌表；确认 RTSP 端口（554 / 8554） |
| 一直超时、8 秒没帧 | 不在线 / 不同网段 / 防火墙 | ping 一下；确认同一网段；关掉摄像头侧防火墙 / 开 RTSP 服务 |
| 有声音没画面 / 花屏 | 编码是 **H.265** | 摄像头后台把主码流或子码流切成 H.264；或改用子码流 |
| 画面很卡、延迟高 | 主码流太大 | 改用子码流地址（`102` / `stream2` / `subtype=1`） |
| `Protocol not found`（ffmpeg） | ffmpeg 没编进 RTSP | 换官方完整版 ffmpeg（gyan.dev / BtbN 的 build） |
| `Invalid data found when processing input` | 地址不对或端口给成了 HTTP | 核对 `rtsp://` 前缀和端口 |
| 连上就断、反复重连 | 摄像头**并发连接数**满了 | 关掉其它客户端（NVR、手机 App、另一个播放器）再试 |
| 本机摄像头黑屏 | 被别的软件独占 / 隐私设置 | 关掉会议软件；Windows 设置 → 隐私 → 摄像头 → 允许桌面应用访问 |

---

## 8. 隐私与凭据

- RTSP 地址里**带着密码**。别把它写进要提交的代码、别贴到公开的群或 issue 里
- 日志和面板上，插件会把凭据打成 `//***@`
- 配置只存在本机 `~/.dsh/camera-bridge.json`（不落库、不上传）
- 画面只在**你（或模型）真的调 `look_camera` 再 `read_image`** 时才会进模型上下文
