# ② 视觉：YOLO-World 认不出「没有形状」的东西，换本地多模态

> 回到总览：[`docs/引导.md`](../引导.md) ｜ 上一篇：[① 视频源](./1-视频源.md) ｜ 下一篇：[③ 朗读](./3-朗读-本地TTS.md)

## 1. 为什么 YOLO-World 不合适

YOLO-World 是**开放词表检测器**：拿 CLIP 把「词」和「图里的区域」对齐，再按 YOLO 的结构框出来。
它天生只擅长**有边界、有轮廓**的目标。

| 认得不错（有形状） | 认不出来（没有稳定轮廓） |
|---|---|
| 锅、平底锅、炒锅、刀、砧板、碗、盘子、鸡蛋、手、人、灶台、锅铲 | 烟、蒸汽、火苗、水开、油温、焦黄/糊、生熟、泡沫 |

**本仓库实测过**（2026-11-06，三张真实图：蒸汽弥漫的厨房、锅上蒸汽近景、沸腾的水）：

- 阈值压到 `0.10`，`steam` / `smoke` / `flame` / `oil` **一个都没命中**
- 沸腾的水面甚至比蒸汽更「白」——连像素启发式都分不开
- 所以默认词表里把这 4 个类删了（现在还挂在词表里只会让人以为「坏了」）

> 结论：YOLO 负责「**不漏**」（有形状的东西一直在看），
> 「**看懂**」（有没有冒烟、熟没熟）必须交给多模态模型 —— 但**不是**交给云端。

## 2. 为什么不能「每帧发云端多模态」

| 算法 | 数字 |
|---|---|
| 帧率 8fps × 60 秒 | **480 张/分钟** |
| 盯 1 小时 | **≈ 2.9 万张** |
| 每张（448px 也）按几百到两千 token | 一天轻松**几十万～上百万 token** |
| 单次云端 VLM 延迟 | 0.5–3 秒（还排在状态机前面） |

状态机存在的意义就是**省主模型的 token**：供料必须便宜、就近、可控频。
把供料改成「每帧一次云端调用」，等于把省下来的钱又花回去，还更慢。

## 3. 分工：别让任何一层抢别人的活

| 层 | 谁 | 干什么 | 成本 |
|---|---|---|---|
| **供料** | YOLO-World（本机 GPU，每帧 **16–25ms**） | 锅在不在、有没有手、有没有刀 | 显存 1–2GB，几乎不花钱 |
| **看懂** | 本地多模态（VLM），**只在判不了时抽一帧** | 有没有冒烟、是不是糊了、熟没熟 | 显存 6–16GB，0.3–2s/张 |
| **决定** | 对话主模型（云端） | 组织语言、决定要不要开口 | 只在真要「看一眼」时才花 token |

> 一句话：**YOLO 不漏，VLM 看懂，主模型决定。** 别用「每帧发云端」去补「本地显存不够」。

## 4. 本地多模态怎么选

| 模型 | 参数 | 大致显存（4bit） | 单帧延迟 | 中文 | 备注 |
|---|---|---|---|---|---|
| Qwen2.5-VL-3B | 3B | ~4–8GB | 0.3–0.8s | ✅ 好 | **性价比首选** |
| Qwen2.5-VL-7B | 7B | ~8–16GB | 0.5–1.5s | ✅ 好 | 判断更准，中文场景稳 |
| MiniCPM-V 2.6 | 8B | ~12–16GB | 1–2s | ✅ 不错 | 端侧优化好 |
| InternVL2.5-2B / 8B | 2B / 8B | ~5–16GB | 0.4–2s | ✅ 不错 | 工业界常用 |
| moondream2 | 1.9B | ~4GB | 很快 | ⚠️ 弱 | 只做英文短答可用 |

> 数字都是**大致**：取决于量化（4bit/bf16）、输入分辨率、上下文长度、显卡型号。
> 以各模型官方 README 和你的实测为准 —— 别照表买卡。

**按显存选：**

- **≤ 8GB**：Qwen2.5-VL-3B（4bit），或者干脆不装 VLM —— 继续用「主模型兜底看一眼」，只是看一次贵一次
- **12–16GB**：Qwen2.5-VL-7B（4bit）更准；注意给 TTS 留点（见下一篇）
- **≥ 24GB**：7B fp16 / 更大，能同时跑 YOLO + VLM + TTS

## 5. 怎么接（前两步今天就能用）

### 第一步：起一个本地 VLM 服务

Ollama 最省事：

```powershell
ollama pull qwen2.5vl:3b
ollama serve            # 默认 127.0.0.1:11434
```

### 第二步：拿一张真图验证（用插件自己拍的快照）

```powershell
# 先让插件拍一张：面板「拍一张」，或让模型调 look_camera
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\.dsh\camera-bridge\shots\latest.jpg"))
Invoke-RestMethod -Uri http://127.0.0.1:11434/api/generate -Method Post -ContentType 'application/json' -Body (@{
  model  = 'qwen2.5vl:3b'
  prompt = '图里有没有冒烟或糊锅的迹象？只回答「有」或「没有」。'
  images = @($b64)
  stream = $false
} | ConvertTo-Json -Depth 4)
```

> 提问要**短、封闭**（只回答有/没有、或选一个阶段），别要开放式描述 —— 长输出慢且贵。

### 第三步：让它替 YOLO 供料（还没内建）

现在插件里的「眼睛」**仍然只跑 YOLO-World**，界面上的词表、`lookHz` 都是给它的。
要做成内建，需要照 `tools/yolo_worker.py` 写一个 `vlm_worker.py`（同样的 stdin/stdout 一行一条 JSON），
再由状态机按「**YOLO 判不了 + 冷却到了**」去调用。

**这一步目前只有方案，没有实现。** 在实现之前，能用的就是「过渡期办法」：

- 把 `snapCooldownSec` 调大（例如 60），用 `stuckSec` 限制「卡住才看」
- 只在「必须知道」（比如该出锅了）时让主模型看图 —— 做饭模块的「时长 + 必看」就是这么做的
- 词表里别写 `steam` / `smoke` / `flame` / `oil`，它永远命中不了

## 6. 隐私

本地 VLM 不出网：画面从摄像头进入显存，判断结果回状态机，**不经过任何云服务**。
这是它比「云端多模态」更值得投入的另一个理由 —— 厨房、客厅的画面不该随便上传。
