# 引导：第一次装完，先把这几件事定下来

> 这份文档给两种读者看：
> **人** —— 装完插件不知道下一步该配什么；
> **智能体（模型）** —— 第一次装完，系统提示词里会带一段引导，它会照这里一步步问你要数据。

插件把「第一次要弄明白的事」拆成三个主题，**各自独立完成**（做完一件撤一件，全撤完提示词里就干净了）：

| 主题 | 什么时候该看 | 文档 |
|---|---|---|
| **① 视频源** | 没画面 / 不知道 RTSP 地址 / 连摄像头在哪都不知道 | [`引导/1-视频源.md`](./引导/1-视频源.md) |
| **② 视觉方案** | 认不出烟、火、蒸汽、生熟；或者想把「眼睛」换成本地多模态 | [`引导/2-视觉-本地多模态.md`](./引导/2-视觉-本地多模态.md) |
| **③ 朗读延迟** | 它回一句要等太久；想换本地 TTS | [`引导/3-朗读-本地TTS.md`](./引导/3-朗读-本地TTS.md) |

## 这套东西到底怎么分工

```
  说话  →  麦克风  →  SenseVoice（本机转写）  →  会话主模型（云端）  →  朗读桥 / 本地 TTS
  画面  →  摄像头  →  YOLO-World（本机检测，每帧十几毫秒）  ┐
                        └→ 判不了时：抽一帧给本地多模态 / 主模型  ├→ 状态机 → 「该提醒了」
                                                              ┘        （做饭、盯着看）
```

三个容易搞反的地方：

1. **YOLO-World 不是用来顶替主模型的**。它只给状态机**供料**（锅在不在、有没有手），
   图的是「便宜、快、不花 token」；认不出烟、火这类没有形状的东西是它的能力边界，不是 bug。
2. **别用「每帧发云端多模态」去补这个边界**。那是按张计费的，8fps 就是一分钟几百张；
   正确做法是换**本地**多模态，而且只在「YOLO 判不了」时抽一帧问。
3. **朗读慢，多半不是 TTS 慢**。整轮生成、朗读桥排队、浏览器扩展点按钮，任何一段都能让人等半天；
   换本地 TTS 只砍掉「云端合成 + 浏览器」这两段。

## 引导怎么结束

| 方式 | 效果 |
|---|---|
| **出了一帧画面** | 自动结束「① 视频源」这条 |
| 面板上点某条主题的「**了解了**」 | 只撤掉那一条 |
| 面板上点「**全部不用了**」 | 三条全撤 |
| 模型调 `camera_setup`（`action="done"`, `topic=...`） | 同上，可不带 topic 全撤 |

状态记在 `~/.dsh/camera-bridge/引导.json`（和配置文件分开）。想再看一次：面板上点「**再看一次引导**」，
或 `POST /api/camera-bridge/guide`，body `{"action":"reset"}`（带 `topic` 只重开那一条）。

## 给模型的接口

| 想干什么 | 怎么调 |
|---|---|
| 看三条各自到哪一步 | `camera_setup`（`action="status"`） |
| 读某一篇 | `camera_setup`（`action="guide"`, `topic="source" / "vision" / "tts"`） |
| 设视频源并当场试一帧 | `camera_setup`（`action="set_source"`, `rtspUrl="…"`） |
| 结束某条 / 全部 | `camera_setup`（`action="done"`, `topic="vision"`） |
